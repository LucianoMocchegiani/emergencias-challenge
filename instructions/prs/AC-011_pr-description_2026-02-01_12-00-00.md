# docs: documentación del proyecto (docs/, diagrama BD, arquitectura, tecnologías, patrones y referencias en README)

## Resumen

Añade la documentación técnica y de diseño en `docs/`: diagrama de base de datos (Mermaid + imagen), arquitectura (con diagramas de módulos y flujo de petición), ADR (stack inicial), tecnologías (resumen y referencia a ADR), patrones y glosario. El README raíz actúa como punto de entrada único: resumen, Cómo empezar (incl. variables de entorno opcionales), Estructura del proyecto y referencias con intro a cada doc. Cada documento enlaza al final a [README principal]. Se corrige la documentación de GET /contacts/by-phone en src/contacts/README.md (solo number y phoneTypeId obligatorios).

## Motivación

El proyecto carecía de documentación estructurada más allá del README y del objetivo. Se necesitaba documentación de modelo de datos, arquitectura, decisiones (ADR), stack y patrones sin duplicar contenido: tecnologías referencia al ADR; el README raíz resume y enlaza. Además, el README del módulo contacts documentaba GET /contacts/by-phone con typeName, ya eliminado del código.
