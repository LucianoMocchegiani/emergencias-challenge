# feat(activities): Módulo ContactActivities – creación de actividad y búsqueda por contacto y tipo

## Resumen

Se implementó el módulo de actividades (ContactActivities): POST para crear una actividad asociada a un contacto (personId, activityType 'call'|'meeting'|'email', activityDate, description opcional) y GET para búsqueda por contacto y tipo, retornando datos del contacto (firstName, lastName, email, dateOfBirth) y la lista de actividades. Status codes 201, 200, 400, 404.

## Motivación

AC-005 exige el módulo de actividades según docs/objetivo.md: creación de actividad y búsqueda de actividades por contacto y tipo retornando nombre, apellido, email y fecha de nacimiento del contacto junto con las actividades. Sin este módulo no hay endpoints para actividades; AC-006 (Swagger) documentará estos endpoints.

## Cambios Técnicos

### Backend (Node.js/TypeScript)

- **ActivitiesModule:** TypeOrmModule.forFeature([ContactActivity, Person]); declara ActivitiesController y ActivitiesService; exporta ActivitiesService.
- **ActivitiesService:** create(dto): valida que personId exista en Person (404 si no); crea y guarda ContactActivity; retorna la actividad. findByContactAndType(personId, activityType): valida que el contacto exista (404 si no); busca actividades con personId y activityType; retorna { contact: { firstName, lastName, email, dateOfBirth }, activities }. Si no hay actividades, activities: []. JSDoc en clase y métodos.
- **ActivitiesController:** POST /activities con CreateActivityDto (201 Created); GET /activities?personId=&activityType= con validación de params (personId y activityType obligatorios; activityType en call/meeting/email; personId numérico). 400 si params inválidos; 404 si contacto no existe (desde servicio).
- **CreateActivityDto:** personId (IsInt), activityType (IsIn ['call','meeting','email']), activityDate (IsString, IsNotEmpty), description (IsOptional, IsString). class-validator + class-transformer (@Type para personId).
- **AppModule:** Import ActivitiesModule.

### Base de Datos (SQLite)

- Sin cambios en schema; se usa la tabla contact_activities y la entidad ContactActivity ya definidas en AC-002. Índices en personId y activityType ya existen.

### API / Rutas

- POST /activities – Crear actividad (201, 400 si validación falla, 404 si personId no existe).
- GET /activities?personId=&activityType= – Búsqueda por contacto y tipo (200 con { contact, activities }; 404 si contacto no existe; 400 si faltan params o activityType inválido).
