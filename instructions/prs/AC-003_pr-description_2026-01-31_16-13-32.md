# feat(AC-003): Módulo contactos – creación, búsqueda por email, búsqueda por datos personales, edición, eliminación

## Resumen

Se implementó el módulo de contactos en NestJS con las operaciones requeridas por docs/objetivo.md: POST para crear contacto, GET por email, GET por datos personales (query params opcionales), PATCH para editar y DELETE para eliminar. Se usan DTOs con class-validator, ValidationPipe global, status codes 201/200/204/400/404/409 y tsconfig ajustado (commonjs + node) para resolución de módulos locales.

## Motivación

AC-003 exige exponer la API de contactos (Person) sobre el schema ya creado en AC-002. Sin este módulo no hay endpoints para crear, buscar, editar ni eliminar contactos; AC-004 y AC-005 dependen de tener contactos operativos.

## Criterios de Aceptación

- [x] Creación de contacto: POST con body validado; retorna 201 y el contacto creado.
- [x] Búsqueda por email: GET con query param email; 200 con contacto o 404; 400 si email vacío.
- [x] Búsqueda por datos personales: GET con query params (firstName, lastName, dateOfBirth, email); 200 con lista de contactos.
- [x] Edición: PATCH por id; 200 con contacto actualizado, 404 o 400/409 según corresponda.
- [x] Eliminación: DELETE por id; 204 No Content, 404 si no existe.
- [x] Validación de entrada con DTOs; status codes correctos en todos los casos.

## Cambios Técnicos

### Backend (Node.js/TypeScript)

- **main.ts:** ValidationPipe global (whitelist, forbidNonWhitelisted, transform) para validar DTOs y devolver 400 cuando el body no cumple.
- **ContactsModule:** TypeOrmModule.forFeature([Person]), ContactsController, ContactsService; exporta ContactsService.
- **ContactsService:** create (409 si email duplicado), findByEmail, findByPersonalData (filtros opcionales), findOne, update (409 si email duplicado al cambiar), remove; usa Repository<Person>.
- **ContactsController:** POST /contacts (201), GET /contacts/email?email= (200/404, 400 si email vacío), GET /contacts (query params), GET /contacts/:id, PATCH /contacts/:id, DELETE /contacts/:id (204); ParseIntPipe para :id.
- **DTOs:** CreateContactDto (firstName, lastName, dateOfBirth opcional, email) con class-validator; UpdateContactDto = PartialType(CreateContactDto) vía @nestjs/mapped-types.
- **tsconfig.json:** module "commonjs" y moduleResolution "node" (antes nodenext) para que los imports relativos (./contacts.service, ./contacts.controller) se resuelvan correctamente.
- **AppModule:** Import ContactsModule.

### Base de Datos (SQLite)

- Sin cambios en schema; se usa la entidad Person ya definida en AC-002. DELETE elimina en cascada teléfonos, direcciones y actividades (FKs con onDelete CASCADE).

### API / Rutas

- POST /contacts – Crear contacto (201, 400, 409).
- GET /contacts/email?email= – Búsqueda por email (200, 404, 400 si email vacío).
- GET /contacts?firstName=&lastName=&dateOfBirth=&email= – Búsqueda por datos personales (200 con array).
- GET /contacts/:id – Obtener por id (200, 404).
- PATCH /contacts/:id – Editar (200, 404, 400, 409).
- DELETE /contacts/:id – Eliminar (204, 404).

## Riesgos y Plan de Rollback

- **tsconfig:** El cambio a commonjs + node es el estándar NestJS; revertir a nodenext podría volver a provocar "Cannot find module" en imports locales. Rollback: revertir commit de tsconfig si hubiera incompatibilidades con otras herramientas.
- **Email duplicado:** Se devuelve 409; si en el futuro se permitiera duplicado, quitar la comprobación en create y update.
