# AC-006 - Swagger: documentación de todos los endpoints

## Descripción de la Tarea

Configurar Swagger (@nestjs/swagger) para documentar toda la API: contactos (incluyendo teléfonos y direcciones en create/update, búsqueda por número y tipo) y actividades. Incluye DocumentBuilder en main.ts, decoradores en controladores (@ApiTags, @ApiOperation, @ApiResponse, @ApiBody, @ApiQuery, @ApiParam) y decoradores en DTOs (@ApiProperty, @ApiPropertyOptional) para que el esquema de request/response sea visible en la UI de Swagger.

**Comportamiento actual:**
- Los endpoints están implementados (AC-003 contactos, AC-004 by-phone y phones/addresses, AC-005 actividades) pero no hay documentación Swagger expuesta.

**Comportamiento esperado:**
- Swagger UI disponible en una ruta (ej: /api o /docs).
- Todos los endpoints documentados: descripción, parámetros, body, respuestas (200, 201, 400, 404, 409, etc.).
- DTOs expuestos en el esquema de Swagger para que se puedan probar las peticiones desde "Try it out".
- Agrupación por tags (Contacts, Activities).

## Criterios de Aceptación

1. ❌ Al arrancar la app, Swagger UI está disponible en la ruta configurada (ej: http://localhost:3000/api).
2. ❌ Todos los endpoints de contactos y actividades aparecen agrupados por tag.
3. ❌ Cada endpoint tiene descripción (summary), parámetros/body y respuestas documentadas (200, 201, 400, 404, etc.).
4. ❌ Los DTOs de request aparecen en el esquema y se pueden usar en "Try it out" de Swagger UI.
5. ❌ No hay errores de compilación ni warnings relevantes de Swagger.

### Paso 2: Configurar Swagger en main.ts (DocumentBuilder y SwaggerModule.setup)

**Descripción:**
En main.ts, después de crear la app con NestFactory.create, configurar el documento Swagger con DocumentBuilder (título, descripción, versión de la API) y exponer la UI con SwaggerModule.setup en una ruta (ej: 'api' para que quede en http://localhost:3000/api).

**Archivos a modificar/crear:**
- `src/main.ts`

**Detalles de implementación:**
- Importar DocumentBuilder y SwaggerModule desde '@nestjs/swagger'.
- Crear el documento: `const config = new DocumentBuilder().setTitle('Agenda de Contactos API').setDescription('API REST para contactos y actividades').setVersion('1.0').build();`
- Generar el documento: `const document = SwaggerModule.createDocument(app, config);`
- Montar la UI: `SwaggerModule.setup('api', app, document);` (o 'docs' si se prefiere).
- Opcional: añadir .addTag('Contacts', '...') y .addTag('Activities', '...') en el DocumentBuilder para describir los grupos.

**Notas:**
- El orden de configuración: crear app, aplicar ValidationPipe (ya existe), luego Swagger, luego listen.

**Recursos útiles:**
- [NestJS OpenAPI - Bootstrap](https://docs.nestjs.com/openapi/introduction#bootstrap)

### Paso 3: Decoradores Swagger en ContactsController

**Descripción:**
Añadir a contacts.controller.ts los decoradores de Swagger: @ApiTags('Contacts') a nivel de controlador; en cada ruta @ApiOperation({ summary: '...' }) y @ApiResponse para los status codes que devuelve (200, 201, 400, 404, 409, 204 según el endpoint). Para rutas con body usar @ApiBody; para query params @ApiQuery; para :id @ApiParam.

**Archivos a modificar/crear:**
- `src/contacts/contacts.controller.ts`

**Detalles de implementación:**
- @ApiTags('Contacts') en la clase del controller.
- POST /: @ApiOperation({ summary: 'Crear contacto' }), @ApiBody({ type: CreateContactDto }), @ApiResponse({ status: 201 }), @ApiResponse({ status: 400 }), @ApiResponse({ status: 409 }).
- GET /email: @ApiOperation, @ApiQuery({ name: 'email', required: true }), @ApiResponse(200), @ApiResponse(404), @ApiResponse(400).
- GET /by-phone: @ApiOperation, @ApiQuery number, @ApiQuery phoneTypeId, @ApiQuery typeName, @ApiResponse(200), @ApiResponse(404), @ApiResponse(400).
- GET /: @ApiOperation (búsqueda por datos personales), @ApiQuery para cada filtro opcional, @ApiResponse(200).
- GET /:id: @ApiOperation, @ApiParam({ name: 'id', type: Number }), @ApiResponse(200), @ApiResponse(404).
- PATCH /:id: @ApiOperation, @ApiParam, @ApiBody({ type: UpdateContactDto }), @ApiResponse(200), @ApiResponse(404), @ApiResponse(400), @ApiResponse(409).
- DELETE /:id: @ApiOperation, @ApiParam, @ApiResponse(204), @ApiResponse(404).

**Notas:**
- No duplicar lógica; solo decoradores para documentación. Los DTOs se documentan en el siguiente paso.

**Recursos útiles:**
- [NestJS OpenAPI - Operations](https://docs.nestjs.com/openapi/operations)
- [NestJS OpenAPI - Parameters](https://docs.nestjs.com/openapi/parameters)

### Paso 4: @ApiProperty en DTOs del módulo contacts

**Descripción:**
Añadir @ApiProperty() (o @ApiPropertyOptional() para campos opcionales) en cada propiedad de los DTOs de contactos para que aparezcan en el esquema de Swagger y se puedan usar en "Try it out". Mantener los decoradores de class-validator; ambos conviven en el mismo DTO.

**Archivos a modificar/crear:**
- `src/contacts/dto/create-contact.dto.ts`
- `src/contacts/dto/update-contact.dto.ts` (si se usa PartialType de @nestjs/swagger, el esquema se hereda; si se usa @nestjs/mapped-types, añadir @ApiPropertyOptional donde corresponda o usar ApiProperty con required: false)
- `src/contacts/dto/phone-item.dto.ts`
- `src/contacts/dto/address-item.dto.ts`
- `src/contacts/dto/search-by-phone-query.dto.ts`

**Detalles de implementación:**
- CreateContactDto: @ApiProperty() en firstName, lastName, email; @ApiPropertyOptional() en dateOfBirth, phones, addresses. Opcional: example, description en cada @ApiProperty.
- PhoneItemDto: @ApiProperty() number, @ApiProperty() phoneTypeId (type: Number).
- AddressItemDto: @ApiProperty() locality, street, number (type: Number), @ApiPropertyOptional() notes.
- SearchByPhoneQueryDto: @ApiProperty() number, @ApiPropertyOptional() phoneTypeId (type: Number), @ApiPropertyOptional() typeName.
- UpdateContactDto: si se usa PartialType de @nestjs/swagger (SwaggerPlugin), hereda el esquema; si no, documentar campos opcionales con @ApiPropertyOptional.

**Notas:**
- Para usar PartialType de Swagger y que el esquema se genere bien, se puede cambiar el import de UpdateContactDto de @nestjs/mapped-types a @nestjs/swagger (PartialType de swagger). Eso hace que Swagger conozca los campos; class-validator sigue funcionando igual.

**Recursos útiles:**
- [NestJS OpenAPI - Mapped types](https://docs.nestjs.com/openapi/mapped-types)
- [NestJS OpenAPI - CLI Plugin](https://docs.nestjs.com/openapi/cli-plugin) (opcional, para generar @ApiProperty automáticamente)

## Consideraciones Técnicas

### Compatibilidad
- @nestjs/swagger debe ser compatible con la versión de NestJS del proyecto (ver package.json). En NestJS 11, usar la versión de @nestjs/swagger indicada en la documentación oficial.

### DTOs con class-validator y @ApiProperty
- Los decoradores de class-validator (IsString, IsEmail, etc.) y los de Swagger (@ApiProperty) pueden coexistir en el mismo DTO. No eliminar validaciones; solo añadir documentación para el esquema.

### Rutas sin módulo propio (phones, addresses)
- En este proyecto no hay controladores separados para phones ni addresses; están cubiertos por el módulo Contacts (create/update con phones/addresses, GET by-phone). Los tags en Swagger serán "Contacts" y "Activities".
