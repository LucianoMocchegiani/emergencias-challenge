## Descripción

### Problema/Requerimiento

Implementar el módulo de contactos (Person) en NestJS con las operaciones requeridas por docs/objetivo.md: creación de contacto, búsqueda por email, búsqueda por datos personales, edición de datos personales y eliminación de contacto. Usar verbos HTTP correctos y status codes apropiados.

### Comportamiento Actual

- Existe el proyecto NestJS y el schema SQLite (AC-002), pero no hay endpoints de contactos.

### Comportamiento Esperado

- POST para crear contacto (201 Created, 400 si validación falla).
- GET para búsqueda por email (200 con contacto, 404 si no existe).
- GET para búsqueda por datos personales (query params: firstName, lastName, etc.; 200 con lista).
- PATCH o PUT para editar datos personales (200, 404 si no existe, 400 si validación falla).
- DELETE para eliminar contacto (200 o 204, 404 si no existe).
- DTOs con class-validator; respuestas tipadas en TypeScript.

## Criterios de Aceptación

1. [ ] Creación de contacto: POST con body validado; retorna 201 y el contacto creado.
2. [ ] Búsqueda por email: GET con query param email; 200 con contacto o 404.
3. [ ] Búsqueda por datos personales: GET con query params (firstName, lastName, dateOfBirth, email); 200 con lista de contactos.
4. [ ] Edición: PATCH/PUT por id; 200 con contacto actualizado, 404 o 400 según corresponda.
5. [ ] Eliminación: DELETE por id; 200/204, 404 si no existe.
6. [ ] Validación de entrada con DTOs; status codes correctos en todos los casos.

## Detalles de Implementación

### Consideraciones Técnicas
- Decidir si eliminación es física o lógica (objetivo.md no especifica; por defecto física).
- Búsqueda por datos personales: permitir filtros opcionales (todos o parte).
- Consultas parametrizadas; no exponer errores internos en respuestas.

### Dependencias
- Depende de: AC-002 (proyecto NestJS + schema SQLite).
- Bloquea: AC-004 (teléfonos/direcciones asociados a contacto), AC-005 (actividades por contacto).

## Testing

### Escenarios de Prueba
1. Crear contacto y verificar persistencia y respuesta 201.
2. Buscar por email existente y no existente (200 vs 404).
3. Buscar por datos personales con distintos filtros.
4. Editar contacto y verificar cambios.
5. Eliminar contacto y verificar que no aparece en búsquedas.

### Casos Edge a Considerar
- Email duplicado (definir si se permite o 409 Conflict).
- Edición con datos inválidos (400).
- DELETE de contacto con teléfonos/direcciones/actividades (cascade o restricción según diseño).
