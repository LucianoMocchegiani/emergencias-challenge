## Descripción

### Problema/Requerimiento

Configurar y aplicar tests unitarios con Jest (incluido en NestJS) y linter con ESLint para el proyecto. Incluye: configuración de Jest para NestJS (si no está ya), al menos tests unitarios para servicios o controladores críticos (contactos, actividades), y configuración de ESLint con reglas adecuadas para TypeScript/NestJS para estandarizar el código.

### Comportamiento Actual

- El proyecto NestJS puede tener Jest y ESLint por defecto al crear el proyecto con CLI; falta asegurar cobertura mínima de tests y reglas de ESLint alineadas con el stack.

### Comportamiento Esperado

- Jest configurado y ejecutable con `npm run test`.
- Al menos un conjunto de tests unitarios para lógica crítica (ej: ContactsService, ActivitiesService, o controladores) que validen casos de éxito y error (404, 400).
- ESLint configurado y ejecutable con `npm run lint` (o similar); sin errores de lint en el código existente.
- Opcional: script en package.json que ejecute tests y lint (ej: en pre-commit o CI).

## Criterios de Aceptación

1. [ ] `npm run test` ejecuta los tests y al menos los tests de servicios o controladores críticos (contactos y/o actividades) pasan.
2. [ ] Los tests cubren casos de éxito y al menos un caso de error (ej: 404, 400) por módulo crítico.
3. [ ] `npm run lint` (o equivalente) ejecuta ESLint y el proyecto queda sin errores de lint (o se documentan excepciones justificadas).
4. [ ] La configuración de ESLint es adecuada para TypeScript y NestJS (reglas recomendadas o estándar del ecosistema).

## Detalles de Implementación

### Consideraciones Técnicas
- Usar TestingModule de @nestjs/testing para inyectar dependencias en tests; mockear acceso a SQLite o repositorios para que los tests sean unitarios y rápidos.
- ESLint: considerar @typescript-eslint y reglas para async/await, tipos estrictos, etc.; evitar reglas que choquen con estilo NestJS.
- No es obligatorio cubrir el 100%; sí al menos la lógica de negocio crítica (crear contacto, búsqueda por email, crear actividad, búsqueda por contacto y tipo).

### Dependencias
- Depende de: AC-002 (proyecto NestJS), AC-003, AC-004, AC-005 (lógica a testear).
- Bloquea: ninguno.

## Testing

### Escenarios de Prueba
1. Ejecutar `npm run test` y verificar que todos los tests pasan.
2. Ejecutar `npm run lint` y verificar que no hay errores (o listar y corregir).
3. Añadir un test que falle intencionalmente y verificar que el pipeline de test lo detecta.

### Casos Edge a Considerar
- Tests que dependen de base de datos: usar mocks o SQLite en memoria para no depender de archivo .db en CI.
- ESLint y Prettier: si se usa Prettier, asegurar que no hay conflicto con ESLint (ej: eslint-config-prettier).
